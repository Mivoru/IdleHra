## Global Constraints

- **Task 14 touches the hot auth-validation path** (every REST request via
  `TryResolveAuthenticatedPlayerAsync`, and the WebSocket handshake). Keep
  the added check to one indexed lookup; do not introduce an unbounded or
  per-message cost.
- **Task 14 must not mass-log-out the existing player base on deploy.** The
  new `CurrentSessionNonce` column is additive with no backfill (existing
  rows get `NULL`); treat `NULL` as "no restriction" so a JWT issued before
  this change keeps working until its natural ≤24h expiry. Enforcement only
  begins the moment an account's row gets a real nonce value (next login,
  logout, or password reset after deploy).
- **Task 14's single nonce column means "one live access-token lineage per
  account,"** matching the existing WebSocket single-session-eviction design
  (`RedisPlayerSessionLock.ForceAcquireAndEvictAsync`) rather than inventing
  per-device session tracking. This is a deliberate scope limit, not an
  oversight — full multi-device session management is out of scope.
- **Tasks 17 and 19 both touch `GrantVillagePassiveProductionAsync`
  (`server/FolkIdle.Server/Engine/OfflineSimulationEngine.cs:299-400`).**
  Land 17 first; 19 builds on the same catch block and clamp sites.
- **Task 19 is a wire change**, contrary to the audit's "Risk: very low"
  label — `TickStatePayload`'s `Offline*` fields are already on
  `StateUpdatePacket` and copied by one hand-written object initializer in
  `SimulationEngine`; a new field needs the same treatment (see the
  `add-command` skill) or it silently carries nothing, exactly the defect
  `StateUpdatePacketFieldCoverageTests`'s own doc comment describes
  (`FishingMasteryXp`/`HerbalismMasteryXp`, added and never assigned). Run
  `npm run generate:protocol` after adding the field; never hand-edit
  `protocol.generated.ts`.
- **Every new/changed server test seeds its own rows** and, where a task
  touches `PlayerSessionRegistry`/notification queues, passes a fresh
  instance rather than the xUnit collection's shared fixture registry —
  matching the convention `BreedingRoundOneTests.cs:116` and the gold-sync
  plan both established.
- **Never hand-write a wire type.** Task 19's client-side field arrives
  through `protocol.generated.ts` only.

```csharp
public static async Task<Guid> RevokeRefreshTokenAsync(RetryingDbContextOptions authOptions, string rawToken)
{
    if (string.IsNullOrWhiteSpace(rawToken)) return Guid.Empty;

    byte[] hash = HashRefreshToken(rawToken);
    long now = DateTimeOffset.UtcNow.ToUnixTimeSeconds();

    await using var db = new FolkIdleDbContext(authOptions.Options);
    var row = await db.PlayerRefreshTokens.SingleOrDefaultAsync(r => r.TokenHash == hash && r.RevokedEpoch == 0L);
    if (row == null) return Guid.Empty;

    row.RevokedEpoch = now;
    await db.SaveChangesAsync();
    return row.AccountId;
}
```

```csharp
        private static async Task<long> GrantSingleCommodityProductionAsync(FolkIdleDbContext db, long playerId, string itemId, long amountToGrant, long maxStorage)
        {
            if (amountToGrant <= 0) return 0L;

            var commodity = await db.CommodityRecords
                .FromSqlRaw("SELECT * FROM \"CommodityRecords\" WHERE \"PlayerId\" = {0} AND \"ItemId\" = {1} FOR UPDATE", playerId, itemId)
                .SingleOrDefaultAsync();

            long currentStorage = commodity?.Quantity ?? 0L;
            long grantedAmount = Math.Min(amountToGrant, Math.Max(0L, maxStorage - currentStorage));
            long overflow = amountToGrant - grantedAmount;
            if (grantedAmount <= 0)
            {
                return overflow;
            }

            if (commodity == null)
            {
                db.CommodityRecords.Add(new CommodityRecord { PlayerId = playerId, ItemId = itemId, Quantity = grantedAmount });
            }
            else
            {
                commodity.Quantity += grantedAmount;
            }

            return overflow;
        }
```
