### 35a. Compiler warnings in `NetworkBroadcastSystem.cs`

**Findings.** They were taken from CI's own annotations on run `35906426769`,
which is better evidence than a local build. Four warnings, each emitted twice
(Build and Test, Client Checks):

| Line | Warning | Cause | Fix |
|---|---|---|---|
| 5205 | CS8601 possible null reference assignment | `Username = names.TryGetValue(other, out string? name) ? name : "(unknown player)"`. `names` is built from `PlayerRecord.Username` (`string?`), so `name` can be null even when found | `Username = names.TryGetValue(other, out string? name) && name != null ? name : "(unknown player)",` (a found-but-null username now also shows "(unknown player)" instead of an empty field, which is the intended output) |
| 5471 | CS8604 possible null argument `matchExpression` to `ILike` | `EF.Functions.ILike(p.Username, username)`, where `Username` is `string?` | `.Where(p => p.Username != null && EF.Functions.ILike(p.Username, username))`. This translates to `"Username" IS NOT NULL AND "Username" ILIKE @p`, which is identical in result because `NULL ILIKE x` is never true. Prefer this to `p.Username!` because it states the truth rather than silencing it |
| 5652 | CS0168 `ex` declared but never used | `HandleStatsOnline`'s `catch (Exception ex)` returns a 500 and logs nothing | Log it, in the file's own style: `Console.WriteLine($"Stats online failed: {ex.Message}");` as the first line of the catch. | 9562 | CS8600 converting possible null to non-nullable | `req.TryGetValue("text", out string message)` on `Dictionary<string,string>`, whose `out` is `[MaybeNullWhen(false)]` | `out string? message`. ### 35c. 165 items without art: a ranked list for the owner

**Findings.** `client_web/src/lib/ui/sprites.missing.txt` (generated by
`client_web/scripts/generate-sprites.mjs`, `MISSING_ART_BUDGET = 165`, which
may only fall) lists 165 of 330 `items.json` entries. They are grouped as crafting
materials 46, gathering & profession 46, consumables 3, other 70. Task 33

`mat_rabbit_foot`, `mat_wolf_hide`, ... id 250+) are the **canonical**
per-monster drops of the 25-monster canon, not the legacy set. They are likely
the most visible gap of all, because every kill in region 1 shows one.

**Ranking method.** Score = *how many players see it* × *how often*, from
these sources:

1. **Production holdings (the strongest signal).** Supabase, read-only MCP:
   ```sql
   select "ItemId", count(distinct "PlayerId") as holders, sum("Quantity") as total
   from "CommodityRecords" group by "ItemId";
   ```
   Join by `ItemId` slug to `items.json` `BaseId`. Players are few (29
   accounts, mostly throwaways), so exclude usernames matching `exercise%` and
   weight by holders more than by quantity.
2. **Reachability in code (for items no one holds yet):**
